# v0.3 听读复习与遮挡约定

## 手机端行为

导航合并为「听读复习」。同一张卡可以阅读、收听和回想；没有浮动播放器。自由听读不会自动计入记忆结果。音频保留仅一次、循环本卡、同科随机连播；随机连播每轮洗牌一次，同科播完即停，文字随音频切换。耳机切换继续受同科边界约束。

新进入卡片时，所有有效标记默认遮住。初始按钮为「不记得／记得」：

- **记得**：只揭示，不立即保存 Good。核对后点「下一张」才确认 Good；也可以点「记错了」保存 Again，随后只剩「下一张」。
- **不记得**：保存 Again 并揭示，随后只剩「下一张」。保存失败时保留原界面，允许重试。
- 下一张从同仓库、同科目的到期或未完成卡中随机选择；已到时间的待巩固卡优先，有其他候选时避免立刻重选当前卡。
- 一次答错后，至少间隔 **45 秒**才允许再次确认，需要**连续两次**确认记对才完成当天复习；中途再错重置为两次。未完成的次数跨刷新、离线重启和跨天保留。单科仅剩一张且还在间隔中时，返回复习列表并显示倒计时，不伪造完成。
- 初始记得、且未答错的卡，核对确认一次即完成当天复习。当天完成后从到期队列暂时移除；自由浏览仍可进入。

FSRS 使用 Again/Good、目标保持率 0.95、最长 **5 天**。当天巩固完成后下次间隔限制在 **1—5 天**，中间巩固用45秒队列控制。旧的长间隔记录按「上次评价 + 5天」参与到期判断，不删除原事件；重新评价后写入新间隔。这是本软件的备考策略，不声称复刻扇贝内部算法，也不把当天完成当作独立测评掌握。

每日边界采用设备本地日期。`Review.practice` 为可选运行字段，包含 `day`、`remaining`（0/1/2）、`ready_at`；与 FSRS 和事件日志在同一 IndexedDB 事务保存。v1旧备份继续兼容；新备份带待巩固次数，恢复前校验并按记录时间合并。禁止把该字段写回教学主模型或内容清单。

## Muse 的正文标记

仅在阅读版 Markdown 的需要回忆部分外包裹半角双花括号：

```markdown
**名词 A**：{{需要背诵的定义。}}

- 适用条件：{{条件一、条件二。}}
- 核心关系：{{先有原因，再有结果。}}

| 名词 | 定义 |
| --- | --- |
| A | {{A 的规范定义}} |

公式结论：{{在给定条件下，$x^2\geq 0$。}}
```

术语、标题及必要的回忆线索留在括号外；同一个答案如果在解释、表格中重复出现，也应检查是否需要一起遮挡，避免从其他位置直接看到答案。听觉版保持完整自然的纯文本，**不要写入花括号标记**。MP3不会播放标记，也不会因为播放完成而确认记对。

规则：

1. 支持同一段内多个遮挡，支持段落、标题、列表中的段落和表格单元格。组内可包含粗体和行内公式。
2. 每一对标记必须在同一段或同一表格单元格内闭合；不跨空行、列表条目或单元格，不嵌套。
3. 代码块、行内代码、公式内部、链接文字和原始HTML中的标记不作为指令。需要遮公式时，将标记放在行内公式的 `$...$` 外。不用HTML标签实现遮挡。
4. 多行推导或独立公式块暂不整体遮挡；可把需回忆的结论另写为行内公式并遮住，原推导按教学需要保留。
5. 未标记的旧卡正常显示；闭合错误或嵌套标记按原文显示，防止误隐藏整卡。开发端不会自动判断知识内容应遮哪里。

## 发布与维护

仍使用现有 [内容协议](CONTENT_PROTOCOL.md) 和统一发布流程。没有新建清单字段，不变更 schema_version。仅添加遮挡属于排版修改：沿用 `knowledge_id`、`source_node_id`、`learning_revision`，更新正文文件、`reading_hash`、整条 `content_hash` 与清单版本；听觉文本不变时复用既有 MP3。修改实质知识内容时再判断是否升 `learning_revision`。

不能上传旧全量清单覆盖他人更新，不能把只完成本地文件称作已发布。按已声明ID差量处理，并核对远端发布回执。

## 给 Muse 的复制提示词

> 随身听已支持阅读正文的 `{{需要背诵的内容}}` 遮挡。请先阅读开发项目 `docs/RECALL_MASKS.md` 与 `docs/CONTENT_PROTOCOL.md`，按既有教学依据，为我指定的卡片或之后新发布的卡片设置遮挡：保留名词、标题、必要线索，将定义、要点、条件、因果关系等主要回忆内容放入半角双花括号；检查正文、解释和表格中的重复答案，避免未遮挡处直接泄露答案。不要生成问答卡，不改教学游标和掌握证据。不跨段、不嵌套，公式的标记放在行内公式外，听觉纯文本及MP3不含标记。仅加遮挡时保留原ID与learning_revision，正文及版本哈希按正式工具更新，听觉文本未改则复用音频。每批仅处理我指定的范围，遵守并发差量发布规范，核对远端资源及published回执后才报告发布成功。首次先选最多3张已经讲过的卡让我试用，不批量重写整库。

## 代码边界

- `study.ts`：当天巩固规则、间隔、同科随机选择；不合成音频、不改知识正文。
- `review.ts`：FSRS、时间上限和原子评价；UI揭示不直接记Good。
- `RecallActions.tsx`：三个交互状态，每个状态至多两个评价按钮。
- `MaskedMarkdown.tsx`：Markdown AST局部标记、公式排版及遮挡展示；正文按需加载，未变化时不重复渲染。
- `Toast.tsx`：固定在可视屏幕顶部的消息气泡；普通通知8.5秒后关闭，新版本操作持续可见。
- `playback.ts` / `player.tsx`：单Audio与缓存、洗牌队列、实际播放时长；收听结果不得代替自评。
