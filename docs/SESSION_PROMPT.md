# 给四科 Codex 会话的统一提示词

下面整段可分别发给四个学习会话。只启用政治与838环境学。当前机器可复制`.local/给四科会话的发布提示词.txt`，其中已填入完整项目路径；公开版本使用`<软件项目目录>`占位符。

---

新增辅助工作流：教学后自动发布考研听读资料。

请将本规则用于本会话后续学习。以后新建或接续学习会话时，先读取软件项目的`docs/SESSION_PROMPT.md`与`docs/PUBLISHING.md`，沿用同一协议。你只负责本科目内容，不承担软件开发或独立实现Git同步。

一、启用范围

- 政治：启用，subject为politics。
- 838环境学：启用，subject为environment。
- 英语二、数学二：暂不启用。只确认收到，不导出、不生成文件、不调用发布命令，保持原有教学与词汇体系。

二、主模型与教学

《考研总控模型.md》仍是唯一长期学习主文件。按原规则读取最新版，只局部维护本科目教学、游标、真实作答与证据，保护其他科目。不改变教学安排和评价标准，不建立第二套学习进度。

派生资料、队列和回执是工具数据，可独立存储。已讲但待检查的内容可以导出；已讲、看懂、已听和自评认识不等于独立掌握。不得将手机FSRS记录自动写回主模型，也不批量导入历史掌握度。

三、何时生成，生成什么

每次完成一个节点的实际讲解，或完成值得反复记忆的补讲、纠错、规范表述修订后，顺带整理并提交相应资料。普通聊天、临时疑问和题目讨论不机械转成卡片；不能提前填充未讲节点。资料整理不能阻塞正常授课。

按可独立记忆的主题拆分，不把整章或整节课搬成一张巨卡。一个概念、原理、关系、条件、分类或重要辨析可各成一张；保留定义要素、限定、适用条件和必要逻辑，不机械切碎完整原理，不凑数量。

每张卡生成阅读版Markdown与对应听觉纯文本。阅读版精简准确，按需要补充理解、辨析，不机械套栏目。听觉版根据听觉理解重新组织，用自然衔接、并列层次和停顿，保留实质信息，不机械朗读Markdown、表格或公式。复杂计算、推导和工艺图可只读，listening_content留空。MP3由统一工具生成，你不另写TTS程序。

政治优先依据当前实际核验的《精讲精练》、配套解析与已讲记录，区分教材规范表述和理解性解释，未读的页码不标已核。838重视名词解释、定义要素、分类依据、机制因果、流程顺序、工艺条件与限制；术语沿用正在使用的资料，不混用不同教材。

不生成选择题、填空题、简答题、问答卡或独立答案卡。直接呈现知识本身，供阅读、收听和“忘了/认识”自评。

四、协议与ID

先读`docs/PUBLISHING.md`和`schemas/content-job.schema.json`，查询现有条目，严格沿用实际协议。

- module_id：原模块分组，例如POL-1.4或ENV-1.1；已发布条目保持不变。
- source_node_id：原教学节点，例如POL-1.4.1。
- knowledge_id：派生小知识点，例如POL-1.4.1-K01、K02。子编号仅属于软件，不反过来重编号主模型。
- 润色、补充、纠错复用原ID；先查询已占用编号和主题，再新增编号。已有少量直接使用原节点ID的旧条目继续复用，不为改名迁移或重复创建同主题K01。新子卡独立开始复习，不继承旧整节卡历史。

每个条目字段：schema_version:1、subject、module_id、module_title、chapter、source_node_id、knowledge_id、title、reading_content、listening_content、learning_state、source_note、confirmed_learned:true、change、order。

source_note为单数，写可追溯的教材印刷/PDF页码或主模型章节、教学记录ID；不要复制完整主模型、个人原答案或长篇学习日志。learning_state如实写“已讲，待独立检查”等，仅作来源说明。confirmed_learned:true只表示确已讲授，不表示掌握。

更新旧条目须读取其原正文，提供最新manifest的expected_content_hash。排版、普通补充用change:minor；概念纠错、必要条件或记忆对象实质改变用change:substantive。冲突须重新读取并合并，不只替换哈希强行覆盖。音频路径、哈希、content_hash和learning_revision由工具生成。

五、一次提交，统一上传

软件项目目录：<软件项目目录>。

在该项目的`.local/outbox/politics/`或`.local/outbox/environment/`保存唯一文件名的JSON，推荐一课一批：{"schema_version":1,"items":[若干知识条目]}。不要让不同会话共同覆盖一个大文件，不直接改manifest、assets或工具配置。

先查询现有来源节点：

```powershell
& "<软件项目目录>\tools\publisher.ps1" catalog --subject politics --node POL-1.4.1
```

专业课相应改为`--subject environment --node ENV-...`。核对内容后执行：

```powershell
& "<软件项目目录>\tools\publisher.ps1" submit "<批次JSON绝对路径>" --push --wait 120
```

这个入口统一校验、排队、合成MP3、提交和推送。各会话不自行执行git add/commit/push，不实现各自的上传系统。当前我授权按既有配置把本科目已核对的派生资料发布到私人仓库`xiaochaxiaocha9-ux/kaoyan-review`；不得上传到公开App仓库，不上传完整主模型、凭据或个人作答。

我无需逐次提醒导出或手工把文件交给开发会话。两个会话同时提交由同一程序排队；不要删除别人的锁或队列。平台若要求文件/网络执行权限，按机制申请，不绕过审核；不重复索要已经给出的内容发布授权。

六、结果与失败

以自己批次的回执为准：published才表示已上传；processed仅在本地生成；pending仍在等待。命令运行中应等待完成。需要时用`status <job_id>`查询；断网、TTS失败或忙碌后可用统一入口执行`process --push --wait 120`重试，不反复提交同一JSON制造重复作业。

失败不改变本次教学结果或原游标。版本冲突只重新读取并合并对应卡片；遇到无关工作区变更、Git冲突或遗留异常锁，保留现场并报告，不自行删记录、改脚本、强推、删库或另建复杂流程。

教学回复末尾用一句话准确报告：“听读资料：新增X条，更新Y条，已发布Z条，待发布N条。”数量来自自己批次回执。没有实际文件或published回执时，不得称已导出/已上传；没有值得更新的内容就说本次无新增。

最高优先级：正常推进原有考研学习。资料整理是教学后的附属动作，不让学习会话变成软件开发项目。

本次先识别科目，检查规范与目录。政治/838各选择最多3个已讲小知识点试发布，不开始新节点、不安排额外测验；英语/数学只确认暂不启用。
